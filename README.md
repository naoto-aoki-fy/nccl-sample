# Minimal NCCL AllReduce

This example runs one MPI process per GPU. MPI establishes ranks and broadcasts
an NCCL unique ID; `ncclAllReduce` performs the float SUM reduction on the GPUs.
Each rank contributes 1024 values equal to `rank + 1`.

## Prerequisites and build

The target is Linux aarch64 with NVIDIA HPC SDK 26.9, CUDA 13.3, SDK-provided
NCCL, Open MPI / HPC-X, and SM100 GPUs. Put the required SDK and MPI tools on
`PATH` and configure their library environment as required by your installation.

Supply the existing `config.mk` generated by
[nvccoptions](https://github.com/naoto-aoki-fy/nvccoptions) in this directory.
The Makefile requires it for builds and never generates or overwrites it.
`make clean` also works when `config.mk` is absent. It consumes
`CFLAGS_VENDOR` when compiling, `LDFLAGS_VENDOR` when linking, and
`GENCODE_FLAGS` for CUDA architecture selection. Exported variables such as
`CPATH` remain available to the compiler. No GPU architecture is hardcoded.

```bash
make
```

The build uses `nvcc --forward-unknown-to-host-compiler` and explicitly links
`-lnccl`. `NCCL_HOME` defaults to
`/opt/nvidia/hpc_sdk/Linux_aarch64/26.9/comm_libs/13.3/nccl`.
The Makefile uses its `lib64` directory if present, otherwise `lib`, and embeds
that directory in the executable's runtime library search path. Both locations
can be overridden:

```bash
make NCCL_HOME=/path/to/nccl NCCL_LIBDIR=/path/to/nccl/lib
make clean
```

Use `make clean` before rebuilding with different compiler flags or library
locations. `NVCC` and `NVCCFLAGS` can also be overridden on the make command line.

## Run and GPU mapping

With the requested number of distinct GPUs available and MPI configured for the
machine or cluster:

```bash
mpirun -np 1 ./nccl_allreduce
mpirun -np 2 ./nccl_allreduce
mpirun -np 4 ./nccl_allreduce
```

Ranks sharing a node are identified with `MPI_Comm_split_type` and
`MPI_COMM_TYPE_SHARED`. When all local ranks see the same GPU list in the same
order, each selects the visible device matching its node-local rank. Launch no
more local ranks than available GPUs.

Schedulers can instead set `CUDA_VISIBLE_DEVICES` separately for each process
so that it sees exactly one distinct GPU. In this case every process selects
visible device 0. Setting the same single visible GPU for multiple local ranks
is invalid. For example, `CUDA_VISIBLE_DEVICES=0 mpirun -np 2 ...` generally
exposes the same GPU to both processes and is not a valid two-GPU launch.

Every process calls `cudaSetDevice` before NCCL initialization. The example
compares selected GPU UUIDs within each shared-memory MPI communicator and
aborts if local processes select the same GPU. Missing GPUs or a visible device
list too short for a local rank also produce an explicit mapping error.
For multi-node runs, arrange process placement and GPU visibility through your
MPI launcher or scheduler, and ensure all nodes can load CUDA, NCCL, and MPI.

## Results and errors

Each rank enqueues its input copy and the AllReduce on the same CUDA stream,
synchronizes the stream, copies the output back, and checks every element.
The expected value is `world_size * (world_size + 1) / 2`. Verification rejects
non-finite values and uses tolerance `1e-5 * max(1, abs(expected))`.

For four processes, each rank should print a line like:

```text
Rank 0: CUDA device 0, expected 10, actual[0] 10: PASS
```

Output order may vary. A failure reports the first mismatching index and value,
and the failing rank returns a nonzero exit status. Normal completion, including
verification failure, frees device allocations, the stream, and the NCCL
communicator before finalizing MPI; the temporary local MPI communicator is
freed after GPU mapping.

MPI, CUDA, and NCCL calls are checked. Fatal errors identify the API call and
MPI rank, then use `MPI_Abort` to prevent peers from hanging in collectives;
process termination releases remaining resources on that path. Initialization
or finalization errors return failure directly when MPI cannot safely be used.

## Review and execution status

The source review retained the existing global and node-local rank handling,
visible-device selection and duplicate UUID detection, rank-zero NCCL ID
generation and MPI broadcast, and NCCL communicator initialization. The data
reduction uses `ncclAllReduce`; MPI only handles bootstrap and GPU mapping.
The input copy now explicitly uses the reduction stream. Stream synchronization
precedes the result copy and verification. Checked cleanup and fatal-error
handling remain in place.

The build retains `config.mk`'s MPI compiler and linker options and exported
`CPATH`, applies `GENCODE_FLAGS` during compilation and linking, and explicitly
links NCCL with a runtime search path. No replacement MPI installation paths or
architecture flags were added. Cleanup now permits a missing `config.mk`.

Tests and validation were intentionally skipped at the user's request. No build
command was executed, and no one-, two-, or four-process run was executed.
The exact commands intended for the target environment are:

```bash
make clean
make
mpirun -np 1 ./nccl_allreduce
mpirun -np 2 ./nccl_allreduce
# Only when four distinct GPUs are available:
mpirun -np 4 ./nccl_allreduce
```

`config.mk` is absent from this checkout and must be supplied before building.
Compiler, MPI, NCCL, runtime library resolution, and GPU availability were not
probed. These commands require the SDK/compiler and MPI environment described
above, compatible NCCL headers and libraries, and one distinct GPU per local
rank with the documented visibility mapping. The embedded NCCL search path must
exist on every node; CUDA, MPI, and transitive library dependencies must also be
available through the target installation's runtime environment. No hardware
correctness or build compatibility result is claimed.
